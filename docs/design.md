# 公開候補の設計

## 境界

AgentMemoryは記録の保存、APIと最小限の人間用UIを担当します。
標準の`template:task:show:before-subtasks`へ記録欄だけを追加し、標準の概要・説明・操作要素を移動しません。
実行時JavaScript、タスク詳細の置換、共通テーマ、エディタ変更は公開候補に含めません。

タスク検索・起票・更新・カラム移動・完了/再開は標準APIを使います。
追加機能は専用テーブルに保存し、本体テーブルに列を加えません。

## 保存と認可

SQLiteのトランザクションで現在内容と監査履歴を一緒に保存します。
要求キーと内容の照合で再試行の重複を防ぎ、コンテキストとメッセージの更新には版番号を要求します。
タスク削除後の数値ID再利用でも過去の記録を新タスクへ混ぜません。

標準のセッション/ユーザーAPI認証、プロジェクト権限、UIのCSRF検証を使います。
追加APIは全権限のアプリケーショントークンを受け付けません。
表示はエスケープし、入力をHTMLとして実行しません。
記録のAI区分や判断者は申告情報で、人間の承認の証明ではありません。

## 採用したトレードオフ

| 採用 | 理由と制約 |
| --- | --- |
| SQLiteを先行対応 | 現在の利用構成で保存・競合・再導入を検証する。他DBを未検証のまま対応扱いにしない |
| 標準JSON-RPCとPython標準ライブラリ | 特定エージェントやSDKに依存せず、標準タスク操作を再実装しない |
| 標準画面への記録欄追加 | UIの変更範囲を記憶機能に限定し、本体更新への追従を容易にする |
| 現在表示を編集/削除し、原文は保持 | 通常画面を読みやすくしながら、訂正の経緯を失わない |
| 会話監視をしない | 記録タイミングと人間の判断確認はエージェント指示で扱う |

判断日時は利用者のタイムゾーンからUTCへ変換します。夏時間の曖昧な時刻は明示的な選択が必要です。
DBへ直接接続できる管理者による改変・消去の防止は対象外です。

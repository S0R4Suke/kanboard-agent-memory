# 既存のKanboardと仕事用Claudeへ追加する

既存のチケット、カラム、スイムレーン、プロジェクト、業務手順はそのまま使います。
このプラグインは記録・再開用のAPIと、標準のタスク詳細に表示する作業ログ・判断履歴を追加します。
MCPサーバーやClaude固有の機能は必須ではありません。

## 1. 導入先を確認する

- 対象プロジェクトのURL・名前・IDを確認する。
- KanboardのバージョンとDBの種類を確認する。確認済みはKanboard1.2.55 / SQLite。PHPは8.1以上。
- MySQL/MariaDB・PostgreSQLでは機能を登録しない。DBを確認できない場合や他バージョンは、業務環境へ入れる前に分離環境で確認する。
- DBと添付、プラグイン・設定をバックアップする。

この配布物の`compose.yaml`は新規試用用です。既存のKanboardやそのデータボリュームを置き換えるために使わないでください。

## 2. プラグインだけを追加する

[v0.1.0-rc.1のRelease](https://github.com/S0R4Suke/kanboard-agent-memory/releases/tag/v0.1.0-rc.1)から`AgentMemory-0.1.0-rc.1.zip`と`.sha256`を取得します。
チェックサムを照合し、`plugins/AgentMemory/Plugin.php`という構造になるように展開します。

DockerではZIPをホストへ展開し、既存サービスへ次のマウントを追加できます。

```yaml
volumes:
  - ./AgentMemory:/var/www/app/plugins/AgentMemory:ro
```

既存のDB・添付マウントは維持してください。次回アクセス時に専用テーブルを作成します。
タスク詳細の説明の下に「作業ログ」「判断履歴」が出ればUIの読込みを確認できます。
標準のタスク概要、Markdown編集、コメント、添付、サブタスクは維持されます。

## 3. 既存のClaudeの操作経路へAPIを追加する

接続先は仕事側の`/jsonrpc.php`です。ユーザー名とユーザーAPIトークンを使います。
全権限の`jsonrpc`アプリケーショントークンは追加APIでは使えません。
既存の連携がユーザーAPIトークンを使用していれば、同じJSON-RPC経路へ[追加API](api.md)を組み込めます。
既存のMCP等に任意のJSON-RPC呼出し機能がなければ、付属Pythonクライアントを併用してください。

複数環境への誤書込みを避けるには、[保存先を固定する手順](workspace-usage.md)に従って`examples/workspace.py`を設定します。
トークンをリポジトリ・Claudeの会話・AGENTS.mdへ書き込まないでください。

確認は対象プロジェクトの確認用タスクで行います。`getAgentContext`、`appendAgentEntry`、`getAgentMessages`の読書きと読み戻し、
コンテキスト更新、別セッションからの`resume`を確認します。APIの引数は[仕様書](api.md)にあります。

## 4. 既存の指示へ追記する

既存のCLAUDE.mdやAGENTS.mdを置き換えず、次のような追記だけを行います。
ツール名・設定ファイルの場所は仕事側の環境に合わせてください。[詳しい例](../examples/AGENTS.md.example)もあります。

```text
既存のKanboard業務手順・対象プロジェクト・チケット選定・カラム運用を維持する。
AgentMemoryが有効な対象タスクでは、以下も行う。
- 作業開始時に現在コンテキストと必要な記録を読む。
- 重要な進展はwork_log、人間が決めたことと理由はdecision、技術的根拠や検証はhistoryへ残す。
- 作業の区切りで現在コンテキストを更新し、書込み後に読み戻す。
- 別セッションや委任先には対象プロジェクトとチケットIDを渡す。
- 対応タスクが曖昧なら推測で書き込まず確認する。
```

このプラグインは会話を自動で記録しません。接続を設定しただけではログや判断履歴は埋まりません。
最初の数件は、記録漏れ・重複・カラムとの不整合・再開時に足りない情報を確認してください。
